# Menu UI — Fidelity / Audit Log

Per the agreed approach ("recomp-verified + audit log"): the menu **screens, handlers
and navigation are loaded VERBATIM from the stock PS2 DTBs** (literal 1:1, zero
judgement). The **engine the scripts run on** (interpreter builtins, UI-class message
behavior, the transition protocol, focus, render, and the game-side objects the
scripts call) cannot be transcribed judgement-free from the recomp (it is
register-level emulated PPC). So every **non-verbatim** engine decision is recorded
here with its source. Nothing in the engine layer ships without a source tag.

## Source tags
- `[VERBATIM]` — the behavior IS the stock DTB data; we load/execute it unchanged.
- `[DTB-SURFACE]` — *that* this message must exist is dictated by the DTB data (some
  script sends it); only the *how* needs a source below.
- `[RECOMP sub_XXXXXXXX]` — behavior verified by reading that recomp function
  (`generated/gh2test_recomp.*.cpp`), cited by address.
- `[HARMONIX]` — documented Sandbox/Milo engine semantics (community-confirmed),
  consistent with the DTB usage.
- `[INFERENCE]` — an unavoidable inference not yet pinned to a recomp function.
  EVERY such entry is a known debt to discharge (or accept) before "done".

- **Windowed menu render WIRING — `[STRUCTURAL]`.** `menu_app.cpp` (ghogx_ui_render):
  boots the engine and renders the current screen's panel MILOs via the existing
  3-D `MiloSceneRenderer` (GH2 menus are 3-D scenes, not 2-D quads); Confirm/Back
  drive the real `SELECT_START_MSG`/`pop_screen`; the scene reloads on screen change.

  - (1) panel **textures** — FIXED. Was a use-after-move bug (mats moved into the
    combined scene before reading `diffuse_tex`); now 16/16 load + upload
    (main.milo 9/9 mm_brick03/mainmenu/mm_flyers…; helpbar 7/7).
  - (2) **camera** — RESOLVED via the real game camera. `decode_cam` was broken: it
    parsed a Cam as a standalone Trans, but a Cam is **version-12 + an embedded Trans**
    (version 9 then the matrix with NO meta skip) + world matrix + params — so it read
    the matrix and near/far/fov from the wrong offsets (eye in-plane, fov=1060). Fixed
    in `milo_scene.cpp`: a Cam's local-matrix translation IS the eye = `meta.cam`
    (0,-768,0) along -Y, fov **0.602** rad (verified from the raw metacam.milo bytes).
    `menu_app` now frames with that real camera (no multipliers) → the **poster fills
    the screen** as GH2 frames it, so everything sized to the poster (the menu text) is
    the right size.
  - (2a) **brick wall tiling — RESOLVED.** With the real (close) camera the wall
    bricks were huge because `decode_mat` ignored the Mat's **3x3 texcoord transform**
    (UV scale/offset). The wall vertices are UV[0,1], so the 256px brick tile mapped
    ONCE across the 1600-unit wall. Fixed: `decode_mat` reads the transform and the
    renderer applies `u*scale+offset`. Verified from the bytes — `mm_brick03.mat`
    scales **(4,3)** (the tile repeats 4x3 → small bricks), `mainmenu.mat` is identity.
  - (2b) **textures — RESOLVED.** The flat lavender was the `light.mesh` glow
    overlay (`light_gw.tex`) drawn OPAQUE by the scene renderer (it ignores

    `light*` meshes reveals the real menu: the **brick wall + the "GUITAR HERO II"
    flyer/poster + masking-tape corners render correctly**. Interim = skip the glow
    (`[INFERENCE]` heuristic); PROPER 1:1 FIX = per-material additive blend in the
    renderer (read `MatObj.blend`).
  - (2c) **Menu text/buttons — font format RE COMPLETE (grounded in real bytes+pixels).**
    main.milo has 5 BandButton (main_career/quickspin/multiplayer/tutorial/options.btn) +
    BandLabel (mm_msg.lbl) + 3 Text (song/venue/difficulty). Each **BandButton EMBEDS**
    its label string ("CAREER"…), font name ("impact"), nav target — no localization.
    Font = **impact.milo** (RndDir): impact.tex (512×256), impact.mat, impact.font (8125 B),
    impact.txt. `impact.font` decoded byte-exact from the actual ARK bytes
    (`Guitar Hero II PS2 (USA)/GEN`):
      - `[0x00] i32 version=15`; `[0x04] 9 obj-meta`; `[0x0D] string mMaterial="impact.mat"`.
      - 4 f32: **34.0 (cap height), 50.0 (line height)**, 0, 0.
      - `i32 charcount=104` + **charset[104]** (exact order): `A–Z 0–9` then
        ``!"#$%&'()*+,-./:;<=>?@[\]^_`{|}~`` then Latin-1 accents `©®¡¿À…ß`, **space last**.
        UPPERCASE only.
      - `u8 flag=1` + `i32 kerncount=480` + **kern[480]**: 8 B each =
        `[u8 left][u8 right][i16 sign-ext][f32 kern]`. kern is em-fraction (±1/34 ⇒ ±1 px
        at cap-height 34). Pairs A(/AV/AW/AY… verified. **Loaded byte-exact.**
      - self-name string "impact.font" + a short trailer (34/512, 50/256), then a
        **sparse/segmented per-glyph region** (16-B-strided clusters at odd offsets).

    width/x sequences appear in NO encoding (int8/int16/f32 over /512,/256,/34); the rect
    data is sparse+segmented and only the recomp `RndFont::Load` (register-level PPC) would
    decode it byte-for-byte. **Not needed:** the glyph rectangles ARE the literal pixel
    locations in impact.tex (ground truth). The atlas is a **5-row variable-width packed**
    layout; rows detect cleanly by alpha projection and map **1:1 to the charset order**
    (row0 A–W=23, row1 X–Z0–9 + 15 punct=28, row2 18 punct + ©®¡¿ÀÁÂ=25, rows3–4 accents).
    So glyph rects are **derived from the decoded atlas at load** (`[VERBATIM]` pixels +

    inter-glyph **advance/tracking** (not stored decodably) — seeded from ink-width + small
    tracking, to be pinned against a GH2 screenshot. `[INFERENCE: advance/tracking only]`

### Verbatim-handler vs engine-primitive (the key reduction)
A `Class :: msg` for which some `{new Class ...}` body defines `(msg ...{...})` is a
SCRIPTED HANDLER → loaded + executed VERBATIM by loader/interp (e.g. `GHPanel ::
reset_player_settings / update_song_info / set_up_bands`). Only messages SENT but
never DEFINED as a handler are true engine primitives needing grounded C++:
- UIComponent/GHPanel/GHScreen/UIPanel core: set/get/has, enable/disable, set_focus/
  update_focus, set_showing, find, set_button_text/set_button_state, set_message,

  go_back, handle_select, set_volumes, set_paused, turn_off_ambient/reset_ambient …

  MultiSelect*/SliderPanel/GuitarDisplay/EndGame/Charsys/…): non-handler messages →
