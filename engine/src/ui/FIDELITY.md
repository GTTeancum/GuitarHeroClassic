# Menu UI — Fidelity / Audit Log

Per the agreed approach ("recomp-verified + audit log"): the menu **screens, handlers
and navigation are loaded VERBATIM from the stock PS2 DTBs** (literal 1:1, zero
judgement). The **engine the scripts run on** (interpreter builtins, UI-class message
behavior, the transition protocol, focus, render, and the game-side objects the
scripts call) cannot be transcribed judgement-free from the recomp (it is
register-level emulated PPC). So every **non-verbatim** engine decision is recorded
here with its source. Nothing in the engine layer ships without a source tag.

## Source tags
- `[VERBATIM]` — the behavior IS the stock DTB data; we load/execute it unchanged.
- `[DTB-SURFACE]` — *that* this message must exist is dictated by the DTB data (some
  script sends it); only the *how* needs a source below.
- `[RECOMP sub_XXXXXXXX]` — behavior verified by reading that recomp function
  (`generated/gh2test_recomp.*.cpp`), cited by address.
- `[HARMONIX]` — documented Sandbox/Milo engine semantics (community-confirmed),
  consistent with the DTB usage.
- `[INFERENCE]` — an unavoidable inference not yet pinned to a recomp function.
  EVERY such entry is a known debt to discharge (or accept) before "done".

  - (1) panel **textures** — FIXED. Was a use-after-move bug (mats moved into the

  - (2) **camera** — RESOLVED via the real game camera. `decode_cam` was broken: it

    the matrix and near/far/fov from the wrong offsets (eye in-plane, fov=1060). Fixed

    (0,-768,0) along -Y, fov **0.602** rad (verified from the raw metacam.milo bytes).

    the screen** as GH2 frames it, so everything sized to the poster (the menu text) is
    the right size.
  - (2b) **textures — RESOLVED.** The flat lavender was the `light.mesh` glow

    `light*` meshes reveals the real menu: the **brick wall + the "GUITAR HERO II"

  - (2c) OPEN: the **buttons** (BandButton: main_career/quickspin/multiplayer/

### Verbatim-handler vs engine-primitive (the key reduction)
A `Class :: msg` for which some `{new Class ...}` body defines `(msg ...{...})` is a
SCRIPTED HANDLER → loaded + executed VERBATIM by loader/interp (e.g. `GHPanel ::
reset_player_settings / update_song_info / set_up_bands`). Only messages SENT but
never DEFINED as a handler are true engine primitives needing grounded C++:
- UIComponent/GHPanel/GHScreen/UIPanel core: set/get/has, enable/disable, set_focus/
  update_focus, set_showing, find, set_button_text/set_button_state, set_message,
  setup, get_button/hide_button/set_button_focus, refresh, update_pos, num_lines,
  go_back, handle_select, set_volumes, set_paused, turn_off_ambient/reset_ambient …
  → ground each in the recomp UIComponent/UIPanel/GHScreen subs.
- Specialized panels (StorePanel/TrackPanel/HudPanel/LagPanel/Tutorial/GuitarSelect/
  MultiSelect*/SliderPanel/GuitarDisplay/EndGame/Charsys/…): non-handler messages →
  recomp class subs.

## Discharged / grounded behaviors
- **All 40 `ui/gen/*.dtb` screens + their handlers — `[VERBATIM]`.** Loaded from the
  stock ARK by `load_all_ui_screens` (`screen_loader.cpp`); **236 objects** registered
  across the ~24-class roster, macros shared (ui.dtb first). Handlers (enter/poll/
  SELECT_START_MSG/custom) execute verbatim through the interpreter. Zero judgement.
- **Class roster registration — `[DTB-SURFACE]`.** Every `{new <Class>}` name in
  STOCK_SURFACE.txt is registered (`register_ui_classes`). One `UiObject` backs all;
  the per-class specialized primitives + the real superclass chain remain open (ledger).
- **`enable`/`disable` target — `[DTB-SURFACE]`.** Resolved from the argument (named
  child if it resolves via `find_path`, else self), so correct for both the panel
  (`{$this disable a.btn}`) and component (`{b disable}`) forms without a class guess.
- **Transition protocol — `[VERBATIM-TRACE]` (menus.md, 195 s verified trace).**
  exit = `screen_change|screen_back -> exit(screen+panels) -> ui_exit[_back] -> unload`;
  enter = `change_proxies -> load -> finish_load -> ui_enter[_back] -> enter`. The
  `screen_back` exceptions (chooseprof/mem_card/bonus_material/credits) fall out of
  "fire screen_back only if the screen defines that handler" — no name list.
  goto=replace; push=overlay (underlying stays loaded + unpolled); pop=exit overlay,
  resume underlying. OPEN `[INFERENCE]`: intra-message screen-vs-panel sub-ordering,
  persistent-panel (meta/helpbar) reload skipping, per-screen scene-state IDs +
  helpbar/focus application (Phase 5/6).
